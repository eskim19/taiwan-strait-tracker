# requirements.txt 의 전이 폐쇄(transitive closure)를 못박는다.
#
# 쓰는 법 — 설치 대상은 여전히 requirements.txt 이고 이 파일은 '제약'으로만 건다:
#
#     pip install -r requirements.txt -c requirements.lock.txt
#
# 이 파일을 -r 로 설치하면 안 된다. 그러면 requirements.txt 가 아무도 안 읽는
# 거짓말이 된다. -c 는 새 패키지를 끌어들이지 않고 버전만 고정하며, 범위가
# 충돌하면 pip 이 조용히 다른 걸 깔지 않고 에러로 멈춘다.
#
# 왜 전이 의존성까지 고정하나. requirements.txt 머리말은 "sklearn 이 조용히
# 바뀌면 코드 변경 0으로 클러스터링 결과가 달라진다"고 써놓고 정작 직접
# 의존성 5개만 고정했다. 그 밑의 scipy·joblib 는 매 실행 새로 풀린다 —
# 막으려던 실패 모드가 그대로 열려 있었다.
#
# urllib3 는 더 직접적이다. collector/fetch.py 가
# `urllib3.util.ssl_.create_urllib3_context` 라는 준(準)비공개 경로를 쓴다.
# 그 경로가 이름만 바뀌어도 수집 전체가 import 시점에 죽는다 — 우리 코드는
# 한 글자도 안 바뀐 채로.
#
# 갱신 방법. 전역 파이썬에 절대 설치하지 말 것(이 노트북의 전역 3.13 은
# easyocr·opencv·matplotlib 와 numpy·certifi 를 공유한다). 일회용 3.12 환경에서:
#     py -3.12 -m venv .venv-lock
#     .venv-lock\Scripts\pip install -r requirements.txt
#     .venv-lock\Scripts\pip list --format=freeze --exclude pip --exclude setuptools --exclude wheel
# ci.yml 의 '락 완전성 확인' 스텝이 이 파일이 낡으면 실패시킨다. 조용히 낡은
# 락은 고정돼 보이는데 안 고정된 상태라, 락이 없느니만 못하다.

# --- 직접 의존성 (requirements.txt 와 값이 반드시 같아야 한다) ---
